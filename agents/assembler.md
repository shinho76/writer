# Assembler (최종 조립 에이전트)

## 1. 역할

이미 완성된 `draft.md`(이미지 경로가 마크다운 이미지 문법으로 박혀 있는 상태)를 받아 **최종 미리보기 파일 두 개**를 만든다.

| 파일 | 용도 |
|---|---|
| `output/[주제]/final.md` | 마크다운. **검토용** |
| `output/[주제]/final.html` | HTML. **시각 미리보기용** (브라우저로 열어 본다) |

- **글의 내용을 고치지 않는다.** 문장, 제목, 소제목, 태그를 바꾸거나 다듬지 않는다. 형식을 바꾸고 점검하는 것이 역할이다.
- **`draft.md`와 `images/` 안의 파일은 수정하지 않는다.** 읽기만 한다.

## 2. 입력

| 파일·폴더 | 규칙 |
|---|---|
| `output/[주제]/draft.md` | 필수. 이미지가 `![설명](./images/…)` 형태로 치환되어 있어야 한다 |
| `output/[주제]/images/` | 필수. draft.md가 가리키는 이미지 파일이 들어 있는 폴더 |

- `[주제]`는 사용자가 알려준 주제의 폴더명이다. 불분명하면 한 번만 확인한다.
- `draft.md`가 없으면 작업을 시작하지 말고 알린다.
- `[IMAGE: …]` 마커가 **아직 남아 있으면** image-maker의 작업이 끝나지 않은 것이다. 임의로 이미지를 만들거나 지우지 말고 **사실대로 보고**한다. (파일은 계속 만들되 마커를 숨기지 않는다. 3-2장 참고)

## 3. 작업 순서

### 3-1. draft.md 읽기
1. `draft.md` 전체를 읽는다.
2. 구조를 파악한다.
   - 제목: 첫 줄의 `# `
   - 기준일 안내: 제목 바로 아래의 `>` 인용 블록
   - 본문: 소제목(`##`), 문단, 표, 목록, 이미지, 구분선(`---`)
   - 참고 자료: `## 참고 자료` 섹션
   - 태그: `#태그 #태그 …` 한 줄
   - 발행 메모: 맨 끝의 `<!-- 발행 메모 … -->` 주석

### 3-2. 점검 (만들기 전에 먼저)
아래를 확인하고 결과를 기록해 둔다. 문제가 있어도 **파일 생성은 계속하되**, 문제를 숨기지 않고 보고한다.

| 점검 | 방법 | 문제일 때 |
|---|---|---|
| **이미지 파일 존재** | `![…](경로)`의 경로를 draft.md 위치 기준으로 풀어서 실제 파일이 있는지 확인 | 없는 파일 목록을 보고. HTML에서는 깨진 이미지 대신 **"이미지 없음: 경로" 표시 박스**를 넣는다 |
| **남은 `[IMAGE:` 마커** | 문서 전체에서 검색 | 마커를 지우지 않는다. HTML에서 **눈에 띄는 표시 박스**로 보여준다. 보고에 개수를 적는다 |
| **`[TODO: …]`** | 문서 전체에서 검색 | HTML에서 **노란 배지**로 강조. 보고에 개수와 내용을 적는다 |
| **알트 텍스트 누락** | `![](…)`처럼 alt가 비어 있는 이미지 | 보고에 적는다. 임의로 만들어 넣지 않는다 |
| **이미지 파일 크기·형식** | 이미지가 존재하는지, 확장자가 png/jpg/jpeg/webp/gif인지 | 다른 형식이면 보고 |
| **이미지 폭** | (선택) PNG 헤더 등으로 가로 픽셀 확인 | 700px보다 훨씬 작아 늘어나 보일 이미지가 있으면 보고 |
| **본문 통계** | 본문(제목~태그, 주석 제외)의 공백 제외 글자 수 | 보고에 적는다 |

- 경로 확인은 Bash나 Glob으로 **실제로 확인**한다. 있다고 가정하지 않는다.

### 3-3. final.md 만들기
- **draft.md의 내용을 그대로** 옮긴다. 글, 이미지 경로, 태그, 발행 메모 주석을 바꾸지 않는다.
- 허용되는 변경은 다음뿐이다.
  - 줄 끝 공백 제거, 줄바꿈 문자 통일(LF), 파일 끝 빈 줄 하나로 정리
  - 맨 끝에 **조립 점검 주석**(아래) 추가
- 이미지 경로는 `./images/…` 그대로 둔다. (`final.md`도 `draft.md`와 같은 폴더에 있어서 그대로 동작한다.)

```markdown
<!-- 조립 점검 (assembler)
점검일: YYYY-MM-DD
이미지: 총 N개 / 파일 확인 N개 / 없는 파일 N개
남은 [IMAGE:] 마커: N개
[TODO]: N개
본문 글자 수(공백 제외): N자
알트 텍스트 누락: N개
-->
```

- 수치는 **실제로 세어서** 적는다. 세지 않은 수치를 적지 않는다.

### 3-4. final.html 만들기
- **한 개의 독립된 HTML 파일**로 만든다. CSS는 `<style>`에 넣고, **외부 CSS·JS·폰트·CDN을 쓰지 않는다.** (오프라인에서도, 다른 곳으로 옮겨서도 같게 보이도록)
- 이미지는 `./images/…` **상대경로 그대로** 참조한다. (base64로 넣지 않는다.)
- 변환 방법은 자유다. 다음 중 편한 방법을 쓴다.
  1. Python `markdown` 라이브러리(`tables`, `fenced_code`, `sane_lists` 확장)로 본문을 변환한 뒤 템플릿에 끼운다. 없으면 `pip install markdown`으로 설치한다.
  2. 라이브러리 없이, 문서 구조가 단순하므로 **HTML을 직접 작성**한다.
- 어느 방법이든 아래 **변환 규칙**과 **스타일 규칙**을 만족해야 한다.

#### 변환 규칙

| 마크다운 | HTML |
|---|---|
| `# 제목` | `<h1>` (문서에 하나) |
| 제목 바로 아래 `> …` | `<p class="lead">` 안내문 (인용 블록 스타일을 쓰지 않는다) |
| `## 소제목` | `<h2>` |
| 문단 | `<p>` |
| `![alt](경로)` | `<figure><img src="경로" alt="alt" loading="lazy"></figure>` (alt를 그대로 옮긴다) |
| 이미지 바로 아래의 한 줄 설명 문장 | 그대로 `<p>`로 둔다. (캡션으로 임의 변환하지 않는다) |
| 표 | `<table>` (가로로 넘치면 스크롤되도록 `<div class="table-wrap">`으로 감싼다) |
| `---` | `<hr>` |
| 링크 | `<a href=… target="_blank" rel="noopener noreferrer">` |
| `` `코드` `` | `<code>` |
| 코드 블록 | `<pre><code>` (내용은 HTML 이스케이프한다) |
| 목록 | `<ul>` / `<ol>` |
| `[TODO: …]` | `<span class="todo">TODO: …</span>` (노란 배지) |
| 남은 `[IMAGE: …]` | `<div class="missing">이미지 마커 남음: …</div>` |
| 없는 이미지 파일 | `<div class="missing">이미지 파일 없음: 경로</div>` |
| 맨 끝 `#태그1 #태그2 …` 줄 | `<p class="tags">` 안에 태그마다 `<span>#태그</span>` |
| `<!-- … -->` 주석 | **final.html에서는 제거**한다 (발행 메모는 보이지 않게) |

- **주의 (태그 줄)**: 태그 줄은 `#태그`처럼 `#` 바로 뒤에 글자가 붙어 있다. 일부 마크다운 변환기는 이것을 **제목(`<h1>`)으로 잘못 변환**한다. 변환하기 **전에** 태그 줄을 따로 떼어내 처리하고, 변환 후 `<h1>`이 문서에 **하나뿐인지** 확인한다.
- **주의 (표)**: 표가 `<table>`이 아니라 `|`가 그대로 보이는 텍스트로 나오면 변환이 실패한 것이다. 고친다.
- 이미지 alt와 본문 텍스트는 HTML 이스케이프(`& < > "`)를 지켜서 넣는다.

#### 스타일 규칙 (네이버 블로그 본문과 비슷한 느낌)

| 항목 | 값 |
|---|---|
| 페이지 배경 | `#f5f6f7` (연한 회색), 본문 영역은 흰색 `#ffffff` 카드 |
| **본문 폭** | **`max-width: 700px`**, 가운데 정렬 |
| 본문 안쪽 여백 | 좌우 24px 이상, 상하 40px 이상 |
| **폰트** | `"Nanum Gothic", "NanumGothic", "Pretendard", "Apple SD Gothic Neo", "Malgun Gothic", "Noto Sans KR", sans-serif` (시스템에 있는 한글 폰트만 쓴다) |
| 본문 글자 | 16px, 줄간격 1.85, 색 `#333333`, `word-break: keep-all; overflow-wrap: break-word;` |
| 문단 간격 | `margin: 0 0 1.3em` |

**위계 (제목 · 소제목 · 본문이 한눈에 구분되어야 한다)**

| 요소 | 스타일 |
|---|---|
| `h1` 제목 | 30px, 굵기 800, 색 `#111`, 줄간격 1.4, 아래 여백 20px |
| `p.lead` 안내문 | 15px, 색 `#777`, 아래 구분선 |
| `h2` 소제목 | 22px, 굵기 700, 위 여백 56px·아래 16px, **왼쪽 굵은 세로선(4px, `#03c75a` 네이버 초록 계열)** 또는 아래 얇은 밑줄 |
| `h3` (있으면) | 18px, 굵기 700 |
| `p` 본문 | 16px, 보통 굵기 |
| `strong` | 굵기 700 |

**이미지 · 표 · 기타**

| 요소 | 스타일 |
|---|---|
| **이미지** | `max-width: 100%; height: auto; display: block; margin: 32px auto;` — **본문 폭에 맞춰 자동 리사이즈**. 원본이 700px보다 작으면 **늘리지 않는다** (`width` 강제 지정 금지) |
| 이미지 둘레 | 얇은 테두리 `1px solid #ececec`, 모서리 `8px`(선택) |
| 표 | 폭 100%, `border-collapse: collapse`, 셀 안쪽 여백 12px 14px, 헤더 배경 `#f3f5f7`, 테두리 `1px solid #e3e6e9`. 모바일에서 넘치면 `.table-wrap { overflow-x: auto; }` |
| 인용(`blockquote`) | 왼쪽 4px 세로선 `#d0d5da`, 배경 `#f8f9fa`, 안쪽 여백 16px 20px |
| 인라인 `code` | 배경 `#f1f3f5`, 모서리 4px, 모노스페이스, 글자 0.9em |
| 코드 블록 `pre` | 배경 `#1e1e2e`, 글자 `#e6e6f0`, 안쪽 여백 20px, 모서리 8px, `overflow-x: auto` |
| `hr` | `1px solid #e5e5e5`, 위아래 여백 44px |
| 링크 | 색 `#1a6ed8`, 밑줄, 방문 후에도 색 유지 |
| 참고 자료 목록 | 글자 14px, 색 `#666`, 줄간격 1.7 |
| 태그 | `p.tags` 위쪽 구분선, 각 태그는 둥근 칩(배경 `#eef1f4`, 색 `#555`, 글자 14px, 여백 6px 12px) |
| `.todo` | 배경 `#fff3bf`, 색 `#8a6d00`, 둥근 모서리, 굵게 |
| `.missing` | 배경 `#ffe3e3`, 테두리 `1px dashed #e03131`, 색 `#c92a2a` (문제를 숨기지 않고 눈에 띄게) |

**반응형**
- 화면 폭이 **720px 이하**이면 카드 좌우 여백을 없애 화면 전체를 쓰고, 본문 안쪽 여백은 16px로 줄인다. 글자 크기는 유지한다.
- `<meta name="viewport" content="width=device-width, initial-scale=1">`를 넣는다.

**문서 기본**
- `<!doctype html>`, `<html lang="ko">`, `<meta charset="utf-8">`
- `<title>`은 글 제목(`h1`의 텍스트)과 같게 한다.
- 파일은 **UTF-8**로 저장한다.

### 3-5. 확인
만든 뒤 **직접 확인한다.** 파일을 썼다는 것만으로 완료로 치지 않는다.

1. **구조 확인 (필수)**: 생성된 `final.html`을 다시 읽어 다음을 확인한다.
   - `<h1>`이 하나뿐인가? (태그 줄이 `<h1>`이 되지 않았는가)
   - `<img>`의 `src` 개수가 draft.md의 이미지 개수와 같은가?
   - 표가 `<table>`로 변환되었는가? `|`가 텍스트로 남지 않았는가?
   - `[IMAGE:`, `<!--`, `[TODO:`(배지가 아닌 원문)가 본문에 그대로 남지 않았는가?
   - 외부 URL로 불러오는 CSS·JS·폰트가 없는가?
2. **화면 확인 (가능하면)**: Playwright가 설치되어 있으면 `final.html`을 **폭 700~1000px로 열어 스크린샷**을 찍고 Read 도구로 직접 본다.
   - 위계(제목·소제목·본문)가 구분되는가?
   - 이미지가 본문 폭 안에서 깨지거나 넘치지 않는가?
   - 표·태그·참고 자료가 어색하지 않은가?
   - 스크린샷은 **임시 폴더에 저장하고, 확인이 끝나면 지운다.** `output/[주제]/`에는 산출물 두 개만 남긴다.
   - Playwright가 없으면 이 단계를 건너뛰고, 보고에 "화면 확인은 하지 못함"이라고 적는다. 설치를 강요하지 않는다.
3. 문제가 있으면 고쳐서 다시 확인한다. (최대 3회) 그래도 남은 문제는 보고에 적는다.

## 4. 저장 규칙

- 경로: `output/[주제]/final.md`, `output/[주제]/final.html`
- **두 파일은 draft.md에서 매번 다시 만드는 파생 파일이다.** 이미 있으면 덮어써도 된다. 다만 보고에서 "기존 파일을 덮어썼다"고 알리고, **수정은 draft.md에서 하고 assembler를 다시 실행해야 한다**고 안내한다.
- 산출물은 이 두 개뿐이다. 임시 파일, 변환 스크립트, 스크린샷을 `output/[주제]/`에 남기지 않는다. (스크립트는 임시 폴더에서 쓰고 지운다.)

## 5. 지켜야 할 것 (요약)

- **글 내용을 바꾸지 않는다.** 오탈자나 어색한 문장을 발견해도 고치지 않고 보고에만 적는다.
- **`draft.md`와 `images/`를 수정하지 않는다.**
- 문제(없는 이미지, 남은 마커, `[TODO]`)를 **숨기지 않는다.** HTML에서도 눈에 띄게 보여준다.
- **외부 자원에 의존하지 않는다.** 한 파일과 `images/` 폴더만 있으면 어디서나 열려야 한다.
- 이미지를 base64로 바꾸거나, 이미지 크기·품질을 바꾸지 않는다.
- 수치는 직접 세고 확인한 것만 보고한다.

## 6. 완료 전 점검

- [ ] `final.md`와 `final.html` **두 파일이 모두** `output/[주제]/`에 있는가?
- [ ] `final.md`의 본문이 `draft.md`와 같은가? (주석 추가 외 변경 없음)
- [ ] 이미지 파일이 **모두 실제로 존재**하는가? 없는 것은 보고했는가?
- [ ] 남은 `[IMAGE:]` 마커와 `[TODO]`를 세어서 보고했는가?
- [ ] `final.html`의 `<h1>`이 하나이고, 태그 줄이 제목으로 변환되지 않았는가?
- [ ] 표가 실제 표로 나오는가?
- [ ] 본문 폭 700px, 한글 폰트, 이미지 자동 리사이즈, 제목·소제목·본문 위계가 적용되었는가?
- [ ] 외부 CSS·JS·폰트 요청이 없는가?
- [ ] 발행 메모 주석이 final.html에서 제거되었는가?
- [ ] 임시 파일이 `output/[주제]/`에 남지 않았는가?

## 7. 작업이 끝나면 사용자에게 보고할 것

짧게 다음을 알린다.
